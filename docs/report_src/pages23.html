01 — How it works

What happens between
the review and the answer

Nothing here is a prompt to a chatbot. Four models do four narrow jobs, each one checkable on its own, and every judgement call is frozen to a file that lives in version control.

Stage one — build a taxonomy from the data, not from a workshop

Split into sentences

4,173 reviews → 9,954 sentences

A mixed review stops being one verdict and becomes several separate claims.

→

Embed each sentence

BGE-small-en-v1.5 · 384-dim · CLS pooled, L2-normalised · local GPU

Meaning becomes geometry, so sentences saying the same thing land near each other.

→

Cluster to discover themes

spherical k-means · k=24 chosen by silhouette

Density clustering was tried first and rejected: 2 clusters, 90% noise.

→

Name once, then freeze

taxonomy.json · 16 aspects · git-tracked

An LLM reads cluster exemplars and writes the taxonomy one time. Labels are never regenerated at runtime, so a theme cannot silently change meaning.

↓
Stage two — measure every sentence against that fixed taxonomy

Assign themes

DeBERTa-v3 zero-shot NLI · 9,954 × 16 = 159,264 entailment passes · multi-label, τ=0.50

Each sentence is tested against each written definition. It can match several aspects, or none — 20.7% match nothing and are excluded rather than forced.

+

Score polarity

RoBERTa (review-tuned) · continuous −1 … +1

Per sentence, never inherited from the star rating. This is the step that recovers complaints buried inside positive reviews.

→

Weight by outcome

OLS · review-level · category + year fixed effects · HC1 robust SE

Ranks aspects by association with the rating, with confidence intervals — not by how loud they are.

→

Extract language

weighted log-odds · informative Dirichlet prior

Which words genuinely distinguish praise from complaint. TF-IDF cannot answer this.

Audited, not asserted

102 sentences judged by hand: 88.2% theme accuracy (CI 80.6–93.1), 95.1% polarity. Two earlier designs scored 56.2% and 82.4% and are documented.

Claims checked mechanically

Every number in every generated brief is parsed and matched to its evidence before it renders. 103 claims, 0 unmatched — and it has caught real errors.

Runs anywhere

No API key, no vendor, no per-call cost. Every model is open-weight and runs on a laptop GPU; outputs are committed so the dashboard opens instantly.

02 — Why it matters

The score tells you who left.
The text tells you why.

Every organisation with a rating already knows its number went down. None of them learn the reason from the number. This reads the sentence instead — which is where the reason always was.

Where the same problem exists today
Live comment streams
Comments arrive faster than anyone can read them. Aspect + polarity per comment turns a feed into a live count of which specific thing people are reacting to — separating a pricing backlash from a delivery outage within minutes, not at the next review cycle.
Support & CSAT
Ticket text inherits the survey score, so friction inside "satisfied" tickets is never counted. The same fix applies, and the outcome you weight against becomes renewal.
App store & marketplace
A five-star review naming a missing feature is the best product input a team receives, and exactly what a star-weighted dashboard throws away.
Employee & patient surveys
Free text beside eNPS or an overall score. Because themes are aspects rather than moods, "manager support" or "discharge communication" can be tracked as improving or worsening over time.
Regulated complaints
Narratives needing triage and an audit trail. A published error rate and an explicit "unassigned" class are what make such a model defensible to a reviewer.
What has to be true before anyone trusts it
Silent mislabelling
A classifier that never abstains will file chatter under a real theme. Guard: an explicit unassigned class, and a hand-judged accuracy figure published beside every result.
False causation
Polarity is read from the same text that produced the score, so the link is mechanical. This is a triage order, never "fix X and the rating rises". Stated in those words.
Thin slices
Small segments produce confident nonsense. Guard: sample-size floors that make the system decline to answer — four of fourteen categories here report no language analysis at all.
Drifting definitions
If a model renames themes on each run, no trend is real. Guard: the taxonomy is frozen in version control, so any change to a theme appears in a diff.
Confident prose
Generated summaries are fluent whether or not they are right. Guard: every numeric claim is machine-checked against the evidence, and the checker's own blind spot is documented.

What it takes to point this at something else: free text, a numeric outcome, and a few thousand rows. Only the taxonomy is rewritten — an afternoon — and every stage after it is unchanged. The finding that makes it worth doing: 17.5% of sentences inside five-star reviews are complaints. Those are the problems your happiest customers are telling you about, and the score is hiding all of them.
